## [Lobste.rs Migrates from MariaDB to SQLite, Sees Performance Gains](https://simonwillison.net/2026/Jul/14/lobsters-sqlite/#atom-everything) ⭐️ 8.0/10

Lobste.rs, a community link aggregation site, successfully migrated its Ruby on Rails application from MariaDB to SQLite over the weekend. The site now runs on a single VPS with improved CPU and memory usage, and reduced hosting costs. This migration challenges the conventional wisdom that SQLite is unsuitable for production web applications, especially those with concurrent writes. It provides a real-world case study demonstrating that SQLite can be a viable and cost-effective alternative to traditional client-server databases for many workloads. The migration involved changes across 188 files, adding 735 lines and removing 593. The primary database file is 3.8GB, and there are separate cache (1.1GB), queue (218MB), and rack-attack (555MB) databases. The site uses SQLite in WAL mode for better concurrency.

rss · Simon Willison · Jul 14, 19:44

**Background**: SQLite is an embedded, serverless SQL database engine that stores data in a single file. It is widely used in mobile apps and embedded systems but has traditionally been considered unsuitable for high-concurrency web applications due to limited write concurrency. Modern SQLite versions with WAL (Write-Ahead Logging) mode allow concurrent reads and writes, making it feasible for many production scenarios. Lobste.rs is a community-driven link aggregation site built with Ruby on Rails.

Multi-agent coordination is a critical yet underexplored capability for LLMs; this benchmark highlights it as a distinct bottleneck beyond individual task competence. The finding that a zero-shot LLM matches a trained MARL agent suggests surprising emergent coordination abilities. The benchmark includes procedurally generated worlds with tasks like exploration, trading, crafting, and combat. Most LLMs achieved only ~6% normalized return, while Gemini 3.1 Pro's zero-shot performance matched a MARL agent trained on 1 billion environment steps.

**Background**: Multi-Agent Reinforcement Learning (MARL) trains multiple agents to interact in shared environments, often requiring extensive environment interaction. LLMs are increasingly used as zero-shot planners in static settings, but their ability to coordinate in dynamic, long-horizon scenarios remains poorly understood. ALEM fills this gap by providing a procedurally generated, open-ended world where agents must collaborate to survive.
