## [阿波罗软件负责人、“软件工程师”一词提出者玛格丽特·汉密尔顿逝世](https://news.mit.edu/2026/margaret-hamilton-computing-pioneer-dies-1007) ⭐️ 9.0/10

据 MIT News 报道，曾领导麻省理工学院仪器实验室软件工程部、主持 NASA 阿波罗制导计算机机载飞行软件开发的计算机科学家玛格丽特·汉密尔顿（Margaret Hamilton）逝世。她因推广“软件工程师”这一称谓而广为人知——在当时，软件还远未被视作一门独立学科，她用这个词来描述自己团队的工作。 汉密尔顿的团队写下了把人类送上月球的代码，并由此确立了现代软件工程中许多如今习以为常的实践，例如基于优先级的任务调度与健壮的错误恢复机制。她的逝世是计算史上的一个重要时刻，也让关于女性在技术领域角色的讨论再次受到关注。 以现代标准衡量，阿波罗制导计算机的内存仅约 72 KB，其飞行软件需要在工厂里由人工把导线穿入磁芯，物理性地“编织”进核心绳索存储器（core rope memory）。汉密尔顿团队设计的异步、优先级调度架构使计算机能够中断并重新安排任务，这一设计在阿波罗 11 号下降过程中计算机过载、触发著名的 1201/1202 报警时起到了决定性作用。

hackernews · muglug · 10月7日 21:16 · [社区讨论](https://news.ycombinator.com/item?id=49998895)

**背景**: 麻省理工学院仪器实验室（即今天的 Draper 实验室）于 1961 年与 NASA 签约，为阿波罗计划研制制导系统，汉密尔顿负责指令舱与登月舱的软件工作。在那个年代，与硬件工程相比，软件常被视为可有可无的附属品，因此她坚持把这项工作称为“软件工程”，是刻意为其争取专业地位。后来，阿波罗 11 号制导计算机的原始源代码在网络上公开，让后人得以直接看到其团队编写的汇编代码。

## [2026 年诺贝尔化学奖据报授予 Kagan 与 Soai](https://www.nobelprize.org/prizes/chemistry/2026/press-release/) ⭐️ 9.0/10

根据一份诺贝尔基金会新闻稿，2026 年诺贝尔化学奖据报授予 Henri B. Kagan 和 Kenso Soai，以表彰他们在手性与不对称催化方面的研究。此次公布的时间点颇为反常，因为诺贝尔奖通常在 10 月初揭晓，而非 6 月。 若消息属实，这将表彰一个支撑现代制药与精细化工制造的领域——在这些领域中，只生成分子的单一镜像形态，往往决定一种药物是有效还是无效甚至有害。该奖项还会把不对称自催化与手性配体设计从冷门课题提升为合成化学的基石。 所提供的官方新闻稿页面没有任何摘要文本，而 6 月的公布时间与诺贝尔委员会传统的 10 月日程严重不符，因此该奖项应向诺贝尔奖官方网站核实。两位被点名的获奖者都以手性研究闻名：Kagan 以不对称氧化反应与手性试剂著称，Soai 则以不对称自催化的 Soai 反应闻名——在该反应中，手性产物会自我放大其對映体过量值。

hackernews · sasvari · 10月7日 09:51 · [社区讨论](https://news.ycombinator.com/item?id=49990470)

**背景**: 手性指的是分子与其镜像无法重合，就像左手与右手一样；这两种形式被称为对映体，它们在生物体系中的行为可能截然不同，因此药物的镜像形态至关重要。不对称催化则是一项长期目标：用少量手性催化剂引导反应，使其主要生成两种镜像形式中的一种，而非各占一半的混合物。生命本身也是手性的——生物几乎只使用单一手性的糖和氨基酸，这正是化学家将手性控制视为一项根本性成就的原因。

## [Anthropic 发布 Claude Haiku 5.5，采用阶梯定价并赠送 API 额度](https://www.anthropic.com/claude-haiku-5-5) ⭐️ 8.0/10

Anthropic 发布了 Claude Haiku 5.5，这是其最小型 Claude 层级中一款更快、更便宜的新模型：当提示不超过 10 万 token 时，输入价格为每百万 token 0.10 美元，输出价格为每百万 token 0.50 美元。此次发布还为 Claude Platform 引入了新的月度 API 额度——Max 5x 订阅用户每月 100 美元，Max 20x 用户每月 200 美元，Team 套餐用户最多可共享 500 美元额度。 便宜且快速的模型是高并发和智能体（Agent）工作负载的主力，因此降低 Haiku 的价格会直接削减多步骤 Agent、数据分析流水线和批量文本生成的运行成本。把 API 额度打包进消费级订阅，也让聊天订阅与开发者平台支出之间的界限变得模糊，这可能改变个人开发者和小型团队为 AI 功能付费的方式。 一旦提示超过 10 万 token，价格就会大幅上升——输入从每百万 token 0.10 美元涨到 0.50 美元，输出从 0.50 美元涨到 2.50 美元——而且这一阶梯阈值只适用于 Haiku，不适用于 Sonnet 或 Opus。一项独立基准测试报告称，Haiku 5.5 的成本约为 Haiku 4.5 的九分之一，同时准确率更高；但长时间的 Agent 上下文很容易越过 10 万 token 的门槛。

hackernews · sfkgtbor · 10月7日 18:01 · [社区讨论](https://news.ycombinator.com/item?id=49996437)

**背景**: Anthropic 的 Claude 系列按能力与成本分为三档：Haiku（最快、最便宜）、Sonnet（均衡）和 Opus（能力最强），其中 Haiku 面向高吞吐、低延迟的任务。LLM API 通常按输入和输出的每百万 token（MTok）计费，因此“阶梯定价”指的是当单个请求超过某个体积阈值后，单 token 价格会上涨。智能体 AI（Agentic AI）系统——即能够自主串联多步骤、工具调用和文件读取的模型——往往会累积非常庞大的上下文，这使得基于提示长度的定价阈值对开发者格外重要。

## [Chrome 重新支持 JPEG XL，推翻此前的移除决定](https://developer.chrome.com/blog/jpeg-xl-in-chrome) ⭐️ 8.0/10

Chrome 现已正式发布对 JPEG XL（JXL）的支持，推翻了此前将这一图片格式从 Chromium 中移除的决定，Firefox 预计也将在稳定版中跟进。据社区讨论，10 月将成为 JPEG XL 从仅 Safari 支持跃升至覆盖大多数浏览器的关键月份。 全球最主流浏览器长期不支持，是制约 JPEG XL 普及的最大障碍，尤其在 Web 场景中；Chrome 此番转向意味着该格式终于有望大规模落地。对 Web 开发者和图片密集的网站而言，他们将多出一个兼具有损与无损压缩、效率优于旧格式的多功能选择。 JPEG XL 由 ISO/IEC 18181 标准定义，既包含改进经典 JPEG 分块变换编码的有损 VarDCT 模式，也包含类似 PNG 的模块化（modular）无损压缩模式。社区成员指出，在较高压缩率的有损场景下 AVIF 可能仍略有优势，而 JPEG XL 更适合被视作极其通用的全能格式，但在 CPU 资源紧张的环境中表现不佳。

hackernews · AshleysBrain · 10月7日 11:25 · [社区讨论](https://news.ycombinator.com/item?id=49991227)

**背景**: JPEG XL 是由联合图像专家组（JPEG）与 Google、Cloudinary 共同开发的图像编码系统，属于免费开放的 ISO 标准，其中“L”代表“长期（long-term）”，意在打造一个可长期使用、面向未来的 JPEG/JFIF 后继格式。它同时支持静态图像和动画的有损与无损压缩。Chrome 此前曾加入过 JPEG XL 支持，随后又将其从 Chromium 中移除，使该格式的支持几乎只剩 Safari，直到此次政策反转。

## [论文质疑 LLM 的纳维-斯托克斯 Lean 形式化证明](https://arxiv.org/abs/2610.08144) ⭐️ 8.0/10

一篇新发表的 arXiv 论文（编号 2610.08144）主张，由大语言模型生成、关于纳维-斯托克斯方程解爆破的 Lean 形式化证明，与其原始的自然语言证明并不对应。作者由此认为，那份通过机器检验的形式化产物并未真正证明自然语言论证所声称的结论。 该质疑直接针对 OpenAI 此前高调宣称的"用 Lean 形式化证明了纳维-斯托克斯爆破"这一成果，并揭示出自然语言到 Lean 的翻译是否忠实，正是 AI 生成形式化数学中最脆弱的一环。如果翻译过程会悄无声息地削弱定理，那么"由大语言模型形式化"本身就不足以证明原始数学命题已被解决。 关键在于，论文质疑的是非形式陈述与形式陈述之间的等价性，而非 Lean 证明本身是否正确——Lean 代码可能完美通过编译，却只证明了一个比自然语言论证更弱的命题。评论者指出，真正决定性的检验是 Lean 定理是否等价于 Clay 数学研究所公布的问题陈述，而把这样的陈述精确表述出来，往往和证明它一样困难。

hackernews · nill0 · 10月7日 15:24 · [社区讨论](https://news.ycombinator.com/item?id=49994145)

**背景**: 纳维-斯托克斯方程描述黏性流体的运动，其光滑解是否会在有限时间内"爆破"（失去光滑性），是 Clay 数学研究所七道千禧年大奖难题之一。Lean 是自 2013 年起开发的证明助手与函数式编程语言，现由 Lean Focused Research Organization 支持，其理论基础是归纳构造演算（CIC），它让数学家把证明写成可被机器逐步检验的代码。形式化验证之所以有价值，是因为它能排除人工审查的疏漏，但前提是形式化陈述必须忠实对应原始的数学命题。
